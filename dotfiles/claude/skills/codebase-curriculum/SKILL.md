# コードベースを題材にした教材づくり

## 前提

- このスキルは、Claude が、ユーザーの手元のコードベースを読み、そのコードベースを理解するための教材と、エンジニアとして成長するための教材を作る手順である。
- 教材は、2つの段階で作る。
  - 段階1: Claude が、学習トピックの一覧の md を作る。ユーザーが、その一覧から学ぶトピックを選ぶ。
  - 段階2: Claude が、ユーザーが選んだトピックについて、解説、問題、模範解答を作る。
- Claude は、段階1の一覧をユーザーが選び終えるまで、段階2に進まない。
  - 理由: 段階2は量が多い。ユーザーが要らないトピックの教材を作ると、作る時間と、ユーザーが読む時間が無駄になる。
- 教材を置くディレクトリは、ユーザーが指定したディレクトリ（多くは、ユーザーがいる教材用のディレクトリ）である。Claude は、題材のコードベースのファイルを変更しない。
- code-tutor との違い: code-tutor は、ユーザーが書いた説明を Claude が添削する。このスキルは、Claude が教材を先に作る。教材で学んだあとに、ユーザーがコードを自分の言葉で説明したくなったら、code-tutor を使う。

## 段階1: 学習トピックの一覧を作る

### 1. 範囲と読み手を確かめる

Claude は、調べ始める前に、次のことをユーザーの依頼から読み取る。読み取れないことだけを、ユーザーに聞く。

- 題材の範囲: どのディレクトリ（サブシステム）を対象にし、どれを対象の外にするか。対象の外のコードは、読まず、出現回数にも数えない。
- ADR などの設計の文書を読んでよいか。読んでよいときは、設計判断（何を決め、なぜその選択肢を選び、何を諦めたか）を、学習の対象に含める。
  - 理由: 設計判断は、コードを読むだけでは分からない「なぜこの形か」を教える。ミドルのエンジニアに上がるための中心の知識である。
- 読み手の水準: 職種、経験の段階（例: ジュニアは脱したが、ミドルには届いていない）、言語ごとの習熟（例: Python は基礎だけ）。
- ユーザーが必ず学びたいと挙げたトピック。
- 教材を置くディレクトリと、一覧の md のファイル名（指定がなければ `learning_topics.md`）。

Claude は、範囲が依頼の途中で変わったら（例: 「この2つのシステムだけに絞る」）、動いている調査を止め、範囲を直してから始め直す。

### 2. コードベースを調べる

- Claude は、Workflow ツールで、調査を並列に行う。このスキルを使うことが、ユーザーが Workflow の利用を選んだことに当たる。Workflow ツールがないときは、Agent ツールのサブエージェントを並列に動かす。
- 段階は、調査 → 統合 → 出現回数の検証 → 漏れの点検 → 執筆 → 日本語の点検 → 点検の反映、の順にする。各段階の役割は次のとおりである。
  - 調査: ファイルのまとまりごとに、1つのエージェントを割り当てる。大きいファイルは、1つのエージェントに1つを割り当てる。ADR を読むエージェントは、コードを読むエージェントと分ける。各エージェントは、概念、設計、文法、組み込み関数、標準ライブラリ、外部のライブラリの使い方、並行処理、通信、デザインパターン、分野の知識（ロボットなど）の候補を、実例（ファイル、行、コード片）つきで返す。
  - 統合: 1つのエージェントが、候補の重複を除き、トピックにまとめる。読み手が基礎しか知らない言語の文法は、まとめすぎない（1つのトピックを、1回の学習で理解できる大きさにする）。各トピックに、出現回数を数えるための grep のパターンを付ける。
  - 出現回数の検証: 分野ごとのエージェントが、範囲の中のコードを grep して、出現回数と、出てくるファイルの数とサブシステムを数える。実例の行番号を、Read で確かめる。
    - 理由: 調査のエージェントが見積もった回数は、担当の範囲の中の数で、外れることがある。選定理由の根拠になる数は、実際に数えた数にする。
  - 漏れの点検: 1つのエージェントが、ユーザーが挙げたトピックが、どのトピックで扱われているかを対応づけ、足りなければトピックを足す。何度も出てくるのに一覧にないものと、汎用的に大事なのに抜けているものも探して足す。価値の小さいトピックは、外す候補として理由とともに挙げる。学ぶ順を、前提の関係に沿って段階に分ける。
  - 執筆: 1つのエージェントが、一覧の md を書く（書式は `references/topic-list-format.md`）。
  - 日本語の点検: ja-reviewer エージェントが点検し、執筆の担当が、妥当な指摘を直す。
- 調査のエージェントには、次の決まりを伝える。
  - 題材のファイルを変更しない。git の操作をしない。プロセスを起動しない。
  - `.env`（`.env.example` を除く）、録音などのデータ、`.git` の中は読まない。認証情報を出力に書かない。
  - 行番号は、書く直前にファイルを読み直して確かめる。
    - 理由: 題材のコードベースは、ユーザーやほかのセッションが同時に編集していることがある。

### 3. トピックを選ぶ基準

Claude は、次の基準のどれかに当てはまるものを、学習トピックにする。基準には記号を付け、一覧の md の中で、トピックごとにどの基準に当てはまるかを示す。

| 記号 | 基準 | 当てはまると判断する根拠 |
|---|---|---|
| A | コードベースで頻出 | grep で数えた出現回数と、出てくるファイルの数 |
| B | 範囲の中の複数のサブシステムに出てくる | 出てくるサブシステムの一覧 |
| C | 設計判断に関わる | 関係する ADR がある |
| D | 汎用的で、読み手の水準の次の段階のエンジニアに必要 | 知らないと起きる誤り（バグ、設計の誤り、安全の問題） |
| E | 読み手の今の習熟からの段差が大きい | 読み手が基礎しか知らない言語で、基礎の範囲を超える文法やライブラリ |
| F | ユーザーが指定した | ユーザーの依頼の文 |

- A の出現回数の線（何回以上を頻出とするか）は、コードベースの大きさに合わせて、Claude が決め、一覧の md に書く。
- 1回しか出てこず、B〜F のどれにも当てはまらないものは、一覧から外す。外したものは、一覧の md の「一覧から外した候補」に、当てはまらなかった基準とともに残す。
  - 理由: ユーザーが、外した理由を見て、トピックを戻せるようにするため。

### 4. 一覧の md を書く

- 書式は、`references/topic-list-format.md` に従う。
- 各トピックに、選定理由を必ず書く。選定理由には、当てはまる基準の記号と、そのトピックに固有の根拠の事実（出現回数、サブシステム、ADR、知らないと起きる誤り、ユーザーの指定）を書く。「重要だから」のような、根拠のない理由は書かない。
  - 理由: ユーザーは、選定理由を読んで、取捨選択を判断する。根拠がないと、判断できない。
- Claude は、執筆のあとで、id が、表、詳細、ユーザーの指定との対応、学ぶ順の間で食い違っていないかを確かめる。

### 5. ユーザーに渡す

Claude は、返答に次のことを書き、ユーザーの選択を待つ。

- 一覧の md の場所と、トピックの数（分野ごとの数）。
- ユーザーが指定したトピックが、どの id で扱われているか。
- 選び方（チェックボックスに `x` を付ける）。
- 動かして確かめていないことや、数え方の限界（例: grep のパターンでは数えられない設計の概念）。

## 段階2: 解説、問題、模範解答を作る

この節は Claude の解釈であり、ユーザーには確かめていない。ユーザーが段階2の進め方を指示したら、その指示に従い、この節を直す。

- Claude は、一覧の md で `x` が付いたトピックだけを対象にする。学ぶ順の案に沿って作る。
- ファイルは、トピックごとに分け、解説と問題を1つのファイル、模範解答を別のファイルにする（例: `topics/<id>_<短い名前>.md` と `answers/<id>_<短い名前>.md`）。
  - 理由: 問題と同じファイルに模範解答があると、ユーザーが問題を解く前に答えを見てしまう。
- 解説は、一般の説明だけで終えず、題材のコードベースの実際の箇所（ファイルと行）を読みながら説明する。設計判断のトピックは、ADR の選択肢と、コードに現れた結果を結び付ける。
- 問題は、用語の定義を聞く問題にしない。「この行を消したら何が起きるか」「この2つのスレッドが同時に動いたらどうなるか」「この ADR の別の選択肢を選んでいたら、コードのどこが変わるか」のように、仕組みを使って予測しないと答えられない問題にする。
  - 理由: 定義を聞く問題は、暗記で答えられ、理解を確かめられない。
- 模範解答には、答えと、答えを確かめる方法（コードの該当行、ログ、小さな実験のコード、公式の文書）を書く。
- 段階2の教材にも、`~/.claude/rules/japanese-document-style.md` と、言語ごとのルール（Python の型ヒント、名前の付け方など）を当てはめる。教材の中の例のコードも、ユーザーのコーディングのルールに従う。
