# ADR に書くことは、アーキテクチャの水準の決定だけにする（すべてのプロジェクトのためのルール）

このルールは、Claude が ADR（設計判断の記録）を書くとき、直すとき、点検するときに当てはめる。ADR の書式や INDEX.md の扱いは、adr スキルとプロジェクトの決まりに従う。

- ADR には、アーキテクチャの水準の決定だけを書く。アーキテクチャの水準の決定とは、プロセスやスレッドの分け方、責務をどこに置くか、プロセスの間の通信の方式、システムが守る条件（例: ロボットは作業者の承諾のあとにだけ動く）などである。
- ADR には、具体的な値を書かない。具体的な値とは、周期、待ち時間、上限、回数、しきい値、ポート番号、測った時間やメモリの量、ライブラリの版、モデルの名前、話す文の文面、言葉の一覧の中身などである。
  - ファイル、プロセス、クラスの名前は、具体的な値に含めない。決定が、ファイルやプロセスの分け方そのものであることがあるためである。この線引きは Claude の解釈であり、ユーザーには確かめていない。
  - 決定を説明するための例（「例:」「たとえば」と断って挙げる文や言葉）は、書いてよい。ただし、例を、いま使っている文面や言葉の一覧として書かない。この例外は Claude の解釈であり、ユーザーには確かめていない。
  - 値は、詳細設計書かコードに書く。ADR からは、「値は詳細設計書に書く」のように、置き場所を示すだけにする。
  - 理由: 値は、試しながら何度も変わる。ADR に値を書くと、値を変えるたびに ADR とコードが食い違い、読み手が ADR の古い値を信じて、誤った変更をする。ADR は、値が変わっても変わらない決定を残すためにある。
  - 例外: 決定そのものを表す数（状態の数、プロセスの数など）は、書いてよい。この例外は Claude の解釈であり、ユーザーには確かめていない。
- Claude は、ADR を書き終えたとき、直し終えたときに、書いた文に具体的な値が入っていないかを確かめる。既存の ADR の文を直すときに、その文に値が入っていれば、値を消して、置き場所を示す形に直す。
