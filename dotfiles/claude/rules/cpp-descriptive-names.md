# C++ の変数と関数の名前（すべてのプロジェクトのためのルール）

## 変数名と関数名に共通すること

- 変数名と関数名は、その値や関数の性質と目的が分かる名前にする。そのために、名前が長くなってもよい。
  - 理由: 名前を読むだけで、何を表すか、何のために使うかが、読み手に伝わるようにするため（可読性）。
- 一語だけの名前（`data`、`result`、`streak`、`count`、`flag`）は避ける。何の値かを表す語を足す。
  - 例: `streak` → `failed_login_streak`、`result` → `latest_health_check_result`。
  - 例外: 慣習で意味が決まっている短い名前（ループの添字の `i`、`j` など）。
- 元の名前の単語が意味をよく表しているときは、その単語を残し、「何の〜か」を表す語を足す。単語ごと言い換えない。
- 語と語の間は、`_` でつなぐ（snake_case）。
  - 例外: 既存のプロジェクトが、別の書き方（camelCase など）で揃っているときは、どちらに合わせるかをユーザーに確かめる。この例外は Claude の解釈であり、ユーザーには確かめていない。
- ソフトウェアエンジニアに通じる用語や略語（`mic`、`vlm`、`url`、`http`、`json`、`gpu`、`api`、`id`、`db`、`cnt`、`res`、`sec`、`ms` など）は、積極的に使ってよい。
  - `img`、`msg`、`tmp`、`val` のような、ほかのよく使われる略語も、同じく使ってよい。
- ただし、略語だけの1語の名前にしない。何の値かを表す語を足す。
  - 例: `cnt` → `retry_cnt`、`res` → `http_res`。
- 名前に足す情報には、何の値か（対象）、確定した値か一時の値か、どの単位か（`_sec`、`_ms`）、真偽値なら何が真か、がある。
- 名前には、処理の手順（キューから取り出した、など）よりも、文脈の上で大事な意味を表す語を選ぶ。特に、その値がどこから来たか（HTTP で別のサーバーから取得した、など）は、読み手にとって大事な情報である。
  - 例: 別のサーバーから取得してキューに預けておいたメッセージを返すとき、`taken_messages` や `dequeued_messages`（キューから取り出したという手順）ではなく、`fetched_messages`（別のサーバーから取得したメッセージ）にする。
- 注意: 情報を足しすぎて、名詞の名前（変数名）や動詞の名前（関数名）が文になってしまうと、かえって可読性が下がる。足す情報は、名詞句や動詞句の形を保てる範囲にとどめる。
  - 例: `parser_skipped_lines`（名詞のはずが、「パーサーが行を読み飛ばした」という文になっている）→ `skipped_lines_by_parser`（名詞句）。

## 変数名

- 変数名は、2語以上で作る。できれば、3〜4語以上を目指す。
  - 例: `files` → `uploaded_files`、`uploading` → `client_is_uploading`。
  - 例外: 上の「一語だけの名前」の例外と同じ。
- ただし、無駄に冗長にしない。足す語は、読み手が「何の値か」を知るのに要る語だけにする。
  - 例: `uploaded_files_vector`（型の `vector` を繰り返している）、`config_value_from_config`（同じ語を繰り返している）のようにしない。
- 真偽値（bool）以外の変数は、物や値を表すので、名前を名詞句にする。文の形にしない。
  - 例: `parser_skipped_lines`（文の形）→ `skipped_lines_by_parser`（名詞句）。
- 動詞を含む変数名には、動作主（誰が、何が）と、目的語（何を）の情報を入れる。名詞句のまま、目的語を中心の名詞にし、動作主は `by_〜` で表す。
  - 例: `skipped` → `skipped_lines_by_parser`、`wait_sec` → `wait_for_server_sec`。
- 名詞だけの変数名は、その物がほかの動作の主語になる（動作をする側）か、目的語になる（動作をされる側）かに応じて、能動か受動かの情報を足す。足すと理解を助けるときに、足す。
  - 主語になる物（能動）の例: `log_writer_thread`（ログを書き込むスレッド）。
  - 目的語になる物（受動）の例: `uploaded_files`（アップロードされたファイル）、`rejected_requests`（拒否されたリクエスト）。
- 真偽値（bool）の名前は、文の形でもよい。何が真なのかが、読んで分かるようにする。
  - 例: `connected` → `db_is_connected`、`server_has_accepted_request`。

## 関数名

- 関数名は、動詞と、その目的語（何に対して行うか）で作る。目的語のない動詞だけの名前（`process`、`handle`、`run`、`update`）は避ける。
  - 例: `process_once` → `process_pending_orders_once`。
- スレッドの本体や、ログを出す関数も、できるだけ動詞と目的語の形にする。名詞の形（`〜_worker`）や、動詞だけの形にしない。
  - 例: `heartbeat_worker` → `send_heartbeats`、`log` → `log_message`。
  - 例外: 起動の入り口（`main`）と、言語やライブラリが名前を決めているもの。この例外は Claude の解釈であり、ユーザーには確かめていない。
