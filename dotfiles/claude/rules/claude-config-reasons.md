# Claude の設定のファイルに書く理由（すべてのプロジェクトのためのルール）

このルールは、Claude が、Claude の設定に関わるファイル（ルール、スキル、エージェント、コマンド、CLAUDE.md）を書くとき、直すときに当てはめる。これらのファイルは、Claude がその場で従う指示である。

- 決定の経緯（いつ決めたか、誰が決めたか、誰が何と言ったか）は書かない。
  - 理由: 経緯は Claude の動きを変えず、Claude が毎回読む量を増やすだけである。
- 理由は、決まりの狙い（何のためか、守らないと何が起きるか）を説明できるときだけ書く。
  - 理由: 狙いが分かると、Claude は、決まりに書かれていない場面でも、決まりの狙いに沿って判断できる。
- 「ユーザーが指示した」「ユーザーが選んだ」は、理由ではない。狙いを説明できなければ、理由の行を書かない。
- 「この項は Claude の解釈であり、ユーザーには確かめていない」という注記は、経緯ではないので、残す。
  - 理由: この注記は、その決まりがまだ確かめられていないことを示し、ユーザーが見直すときの目印になる。

良い例:

```markdown
- Claude は、`code-tutor` スキルを使っている間は、先回り解説を書かない。
  - 理由: `code-tutor` では、ユーザーが自分で説明を書くことが学習の中心である。先回り解説を書くと、Claude が確認問題の答えを明かすおそれがある。
```

悪い例（経緯を書いていて、狙いを説明していない）:

```markdown
- 前提は、原則1文にする。
  - 理由: 2026-11-12 に、ユーザーが「前提は基本的に1文で良い」と指示した。
```
